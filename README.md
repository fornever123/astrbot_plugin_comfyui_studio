## ✨ 这是什么

**Anima 全能绘画台**是一个适用于 [AstrBot](https://github.com/AstrBotDevs/AstrBot) 的本地 ComfyUI 绘画插件。

它做的事情很单纯：**把 ComfyUI 强大的节点工作流，包装成聊天窗口里一句自然的中文。**

你不必再：

- ❌ 打开 ComfyUI 网页，手动改节点、连线、调参数
- ❌ 为了换一个 LoRA 反复回到文件夹翻文件名
- ❌ 记住 `masterpiece, best quality, 1girl, solo...` 这种英文 tag 串
- ❌ 为了下载一个 C 站模型，先研究半天 API Key 怎么申请

你只需要：

- ✅ `/文生图 一名站在海边的少女，逆光，微风`
- ✅ `/图生图 把身上的衣服换成裙子`（附图）
- ✅ 或者直接说：**「帮我画一张夏空在海边的图，用 1号lora」**

剩下的交给 Anima 全能绘画台。

## 🎨 七种绘图模式

| 模式 | 指令 | 说明 |
| --- | --- | --- |
| 文生图 | `/文生图` | 从零生成，支持多核心模型、多个 LoRA、提示词预设、画师串 |
| 图生图 | `/图生图` | 参考图编辑，默认引擎可在 WebUI 选择 Qwen 或 Flux2 |
| 图生图 Flux2 | `/图生图Flux2` | 强制使用 Flux2 Klein 模块 |
| 高清放大 | `/高清放大` | 放大已有图片，支持附图 / 回复 / 会话最近一张 |
| 洗图 | `/洗图` | Flux2 工作流重绘，只取第一张参考图，保留工作流默认提示词 |
| 扩图 | `/扩图` | 向上下左右扩展画布，可独立设置四边像素与羽化 |
| 多角度 | `/多角度` | 水平角 / 垂直角 / 缩放三轴控制视角 |

```text
/文生图 一名站在海边的少女
/文生图 夏空 海边
/图生图 改成夜景
/图生图Flux2 改成夜景
/高清放大
/洗图 保持人物清晰
/扩图 向左右扩展画面
/多角度 从右侧观察
```

> 💡 **提示**：图生图需要在同一条消息中附图，或回复一张图片 / 含图合并转发后发送指令。
> 洗图、扩图、多角度同一条消息附多张图时**只使用第一张**，其余忽略，且不走普通文生图的 AI 优化、翻译、预设或全局 LoRA。

## 🧩 图生图：完全独立的双引擎

这是 Anima 全能绘画台最"较真"的地方 —— **图生图不是文生图的一个开关，而是一个独立子系统。**

### 双引擎，各自成套

| | Qwen 引擎 | Flux2 Klein 引擎 |
| --- | --- | --- |
| 工作流 | `图生图_qwen_edit.json` | `图生图_flux2_klein.json` |
| 核心模型 | 独立 UNet（GGUF） | 独立 diffusion model |
| 文本编码器 | 独立 Qwen VL（GGUF） | 独立 text encoder |
| VAE | 独立 VAE | 独立 VAE |
| LoRA | 独立 LoRA | 独立 LoRA |
| 采样参数 | 独立步数 / CFG / 种子 / 采样器 / 调度器 / 重绘幅度 | 同一套独立参数 |
| AI 提示词模板 | 独立中文编辑规则 | 独立中文编辑规则 |

两套配置**互不覆盖**，切换引擎不会污染对方的设置。

### ⭐ 特别标注：图生图只受「独立 LoRA」影响

> **【特别标注】图生图只受「独立 LoRA」影响。**
> 图生图不会加载文生图的默认 LoRA 列表，也不会参与画风 LoRA 的随机 / 全部自动选择。
> 只有你在指令中**显式写出**的 LoRA 简称，才会在当前这一次图生图任务里临时叠加。

这条规则在插件里是三处同时生效的：

1. **后端强隔离** —— 图生图分支的长期 LoRA 只从 `img2img_lora_name`（或 `img2img_flux2_lora_name`）读取，代码里显式声明并写日志；文生图的 `lora_list` 和画风 LoRA 链路在图生图中被完全跳过。
2. **WebUI 显著标注** —— “图生图”和“图生图 Flux2”两个页面顶部都有蓝色【特别标注】横幅，独立 LoRA 字段本身也带 `★` 高亮边框，一眼就能和文生图 LoRA 区分开。
3. **聊天里也说明** —— 每次图生图任务提交后的开始提示会自动带上这句特别标注，群里的人也能看明白规则。

### 中文编辑，只改你要改的

图生图的 AI 规则和其它模式完全不同：它**只保留你明确要求改动的内容**。

```text
用户：把身上衣服换成裙子
AI 输出：change the outfit to a dress
```

不会擅自补写角色、背景、镜头或画风。未要求改变的内容保持原图不变。

其它图生图特性：

- **保持原图宽高比**，Qwen 参考图默认最长边 1152 —— 小图不放大、超大图按比例缩小，专为 8GB 显存优化
- **工作流自动转换** —— 支持从 ComfyUI 编辑器 JSON 自动转成 API 工作流
- **无加速污染** —— 两套引擎都按你提供的原始无加速工作流运行，不注入加速 LoRA / KV Cache
- **Flux2 支持 1~3 张参考图**，Qwen 支持 1~2 张
- **普通翻译默认关闭** —— 中文编辑句直接交给 Qwen Image Edit 处理

## 📦 LoRA 管理：批量导入 + 免 API 下载

### 批量导入 LoRA

一次性整理整个 LoRA 文件夹，不用一个个点。

**WebUI 批量导入**

1. 进入「LoRA 组」页面
2. （可选）在“批量导入分类”下拉里选好分类
3. 点击 **批量导入 LoRA**，一次选中多个 `.safetensors` / `.pt` / `.ckpt` / `.bin`
4. 插件会逐个导入，实时显示 `正在导入 3/12`、进度条，以及 **N 成功 / M 失败** 和逐条失败原因

**画风 LoRA 同样支持批量** —— 「画风 LoRA」页面的「批量导入画风 LoRA」会自动归类为“画风”并分配简称。

**API 批量接口**（脚本/自动化用）：

```http
POST /astrbot_plugin_comfyui_ai_studio/upload_lora_batch
Content-Type: multipart/form-data

files=<file1>&files=<file2>&files=<file3>
```

返回 `{ ok, count, saved[], failed[] }`，逐文件给出结果。

### LoRA 的完整档案

每个 LoRA 都能独立管理：

- 🏷️ **中文昵称** —— `/loraon 夏空`
- 🔢 **多个指令简称** —— 新旧简称可以并存，不破坏旧习惯
- 📂 **分类** —— 角色 / 画风 / 细节，或自定义分类
- ⚖️ **权重** —— 每个 LoRA 单独设权重
- 📝 **专属提示词预设** —— “指令简称 → 预设内容”映射
- 🎯 **CivitAI 触发词** —— 启用或临时调用时自动加入提示词（普通 tag 不会乱入）
- 🖼️ **预览图** —— 支持拖入本地图片自定义预览
- ⭐ **画风 LoRA 独立模块** —— 随机 / 全部 / 关闭三种自动使用方式

### 免 API 下载 C 站模型

以前的痛点是：下载 C 站模型必须申请 API Key。现在**不需要了**。

在 WebUI 的「C 站下载方式」里三选一：

| 方式 | 行为 | 适合谁 |
| --- | --- | --- |
| `auto`（默认） | 先尝试**免 API 解析**，失败再自动退回 API Key | 大多数人，无脑选这个 |
| `nokey` | **全程免 API Key**，不使用任何 Authorization 头 | 不想申请密钥、只下公共模型 |
| `token` | 始终走 CivitAI API（带 API Key） | 下载受限 / 私有模型 |

免 API 方式支持两种链接：

```text
# ① 直链下载地址（最稳，零解析）
https://civitai.com/api/download/models/123456

# ② 模型页 / 版本页链接（解析页面内嵌 JSON 得到下载地址）
https://civitai.com/models/123456
```

后台实现要点：

- **不发送 Authorization** —— 公共 LoRA 的 CDN 直链本就不需要密钥，带上无效密钥反而会被判定鉴权失败
- **解析页面内嵌 JSON** —— 从模型页的 `__NEXT_DATA__` 里递归定位 `downloadUrl`，完全不碰 `/api/v1`
- **真实文件名还原** —— 免 API 解析只能拿到 `civitai_版本ID.safetensors` 这种占位名，下载完成后用 CDN 响应头的 `Content-Disposition` 还原成真实文件名（含 UTF-8 中文名）
- **失败兜底** —— `auto` 模式下免 API 解析失败会自动改用 API Key，不会白等

无论哪种方式，都支持：

- 📊 **实时进度** —— 阶段、百分比、已下载 / 总字节
- 🔁 **自动重试** —— 自动处理 CDN 重定向、临时限流（429）和断线，重试时重新获取签名地址
- 🔄 **自动刷新** —— 下载完成自动刷新模型和 LoRA 列表
- 🛡️ **安全落盘** —— 先写临时文件，校验大小后再改名，避免半截文件
- 📛 **重名保护** —— 可选“允许覆盖同名文件”，不勾选时自动加短哈希后缀

> 也支持自定义 CivitAI 兼容站，例如把「CivitAI 兼容站地址」设为 `https://civitai.red`。
> 模型链接、预览信息和下载会优先使用链接自身的站点。

## 🧠 内置 Anima 提示词工程师

**不需要额外安装提示词插件** —— Anima 全能绘画台自带完整的提示词工程链路。

- 📜 随插件携带 **Anima3 提示词模板**（`knowledge/提示词模版.txt`）
- 🪶 **低 token 规则**处理普通指令、LLM 绘图和预设翻译
- 🎚️ **默认质量词条** 自动前置：`masterpiece, best quality, score_7, safe`
- 🚫 **默认负面提示词** 自动补全，降低低质图概率

三种提示词来源，按需选：

| 来源 | 行为 |
| --- | --- |
| `astrbot` | 使用 AstrBot LLM 已提取的提示词 |
| `plugin` | 用本插件配置的 AI，根据**用户原话**重新整理成完整 Anima 提示词 |
| `noai` / 无 | 不经过 AI，中文可直接翻译或原样提交 |

开发者模式还能看到「原始输入 → 最终提示词」的完整对照。

## 🚀 安装

### 方式一：插件市场（推荐）

在 AstrBot WebUI 的插件市场搜索 **`Anima 全能绘画台`**，安装后重载插件或重启 AstrBot。

### 方式二：从 GitHub 安装

仓库地址：<https://github.com/fornever123/astrbot_plugin_comfyui_studio>

```bash
# 克隆到 AstrBot 插件目录
cd AstrBot/data/plugins/
git clone https://github.com/fornever123/astrbot_plugin_comfyui_studio.git astrbot_plugin_comfyui_ai_studio
```

目录结构应为：

```text
AstrBot/data/plugins/astrbot_plugin_comfyui_ai_studio/
├── main.py
├── workflow.py
├── prompting.py
├── app.js
├── index.html
├── style.css
├── metadata.yaml
├── _conf_schema.json
└── workflows/
```

安装依赖：

```bash
python -m pip install -r requirements.txt
```

完成后在 AstrBot WebUI 重载插件，或重启 AstrBot。

> 🔌 **随便部署**：插件不绑定任何机器路径。所有「源工作流位置」默认留空，
> 此时直接使用插件自带的 `workflows/` 副本；想换成自己的工作流，只在 WebUI 填一次路径即可。
> 字体、提示词模板同理，留空会自动探测（Windows / Linux / macOS 均已适配）。

### 可配置路径一览

| 配置项 | 留空时的行为 |
| --- | --- |
| ComfyUI 根目录 | 自动探测常见安装位置（C~H 盘、用户目录） |
| 额外模型路径配置文件（`extra_model_paths_file`） | 自动在 ComfyUI 根目录及其上一层寻找 `extra_model_paths.yaml` / `.yml` |
| 各类别模型目录覆盖（`model_dir_overrides`） | 不覆盖，按下面的优先级自动解析 |
| 原始工作流位置 / 各模式源工作流位置 | 使用插件内置 `workflows/` 副本，**无需填写** |
| 可切换 API 工作流目录 | 使用插件内置 `workflows/` 目录 |
| 图片字体（常规 / 粗体） | 自动探测系统中文字体，找不到时回退默认字体 |
| Anima 提示词模板路径 | 使用插件内置 `knowledge/提示词模版.txt` |
| ComfyUI 启动脚本路径 | 自动寻找 `run_nvidia_gpu.bat` 或 `run.bat` |

#### 模型目录是怎么找到的

`<ComfyUI根目录>/models/<类别>` 只是 ComfyUI 的默认约定——很多人会用
`extra_model_paths.yaml` 把 LoRA、VAE、大模型指到别的磁盘。插件因此把三类来源统一解析：

```
手动覆盖（model_dir_overrides） > extra_model_paths.yaml > <根目录>/models/<类别>
```

- 三种来源都会参与扫描，**同一个类别的多个目录会被合并**，所以模型放在哪都能被列出来；
- 控制台的文件夹卡片和「路径」列表会标注每个目录的**来源**（`手动指定` / `额外路径` / `默认位置`），
  默认位置不加徽标；
- 免 API 下载、批量导入、删除 LoRA 等所有写操作都落在**优先级最高**的那个目录上；
- `unet` / `diffusion_models`、`clip` / `text_encoders` 这两组新旧叫法自动互相兜底。

`model_dir_overrides` 支持两种写法（JSON 文本或字典）：

```json
{ "loras": "F:/my_loras", "vae": "F:/my_vae" }
```

## 🧭 快速上手

**第 1 步 · 连接 ComfyUI**

WebUI →「工作流组」→ 填写 ComfyUI 地址（默认 `http://127.0.0.1:8188`），发送 `/comfy状态` 确认连通。

**第 2 步 · 选好工作流**

在「工作流组」和各模式页面选择对应的 API 工作流。插件不会覆盖你的原始工作流，只会生成副本到 `workflows/`。

**第 3 步 · 导入 LoRA**

「LoRA 组」→ 批量导入 LoRA → 给常用的几个设中文昵称和指令简称。

**第 4 步 · 开画**

```text
/文生图 一名站在海边的少女，逆光，微风
```

**第 5 步 ·（可选）接入 AI**

在「AI 与回复」配置 OpenAI 兼容服务，就能用自然语言触发绘图：

```text
帮我画一张夏空在海边的图片，使用 1号lora
```

## 📖 指令速查

### 绘图

```text
/文生图 <提示词>
/图生图 <编辑要求>          # 需附图或回复图片
/图生图Flux2 <编辑要求>      # 强制使用 Flux2 引擎
/高清放大 [--放大=2]
/洗图 <要求>
/扩图 <要求>
/多角度 <要求>
```

### 参数

```text
/文生图 夏空 1号lora 海边 --步数=30 --cfg=5 --种子=-1
/文生图 ai 夏空 海边              # ai 开启 AI 优化，noai 关闭
/文生图 --模型=模型文件名 --负面=不需要的内容
/图生图 变成夜景 --强度=0.6
/高清放大 --放大=2 --强度=0.25
```

上例会同时使用「夏空」提示词预设和「1号lora」LoRA。**临时 LoRA 只在本次任务生效**，不会改变默认启用列表。

## 🛡️ 图片安全审核

与旧的「群聊涩图黑名单」**是两个独立功能**：

- 旧名单 —— 只往负面提示词追加安全词，**降低**生成概率
- 新审核 —— 输入 / 输出端各调用一次多模态模型，命中直接**拦截**

```text
用户附图 ─▶ 输入端审核 ──命中──▶ 群内 @发送者 + 警告（不进 ComfyUI）
                    │
                 未命中
                    ▼
              ComfyUI 生成
                    ▼
输出端审核 ──命中──▶ 群内 @发送者 + 警告（不发图、不发完成回复）
                    │
                 未命中
                    ▼
                正常发送图片
```

- 输入端审核在拿到参考图之后、发送「正在生成」之前执行 —— 命中时不占队列、不先回复开始提示
- 输出端审核在发图之前执行 —— 命中时**只发警告**，不会再发「生成完成，共 N 张」
- 同一张图在一次消息流程中只调用一次审核接口（进程内缓存）

### 配置项

| 配置 | 说明 |
| --- | --- |
| 图片安全审核总开关 | 关闭时完全不检测。默认关闭 |
| 输入端检测名单 | 每行一个群号；填 QQ 号表示只检测该用户；填 `*` / `all` / `全部` 表示所有群聊；留空不检测 |
| 输出端检测名单 | 规则同上，两个名单互相独立 |
| 审核服务地址 | OpenAI 兼容接口，例如 `https://api.example.com/v1`；粘贴带 `/chat/completions` 的完整地址会自动剥离 |
| 审核模型 | 必须是**多模态**模型（如 `gemini-2.5-flash`），纯文本模型无法看图 |
| 审核 API Key | 只保存在 AstrBot 配置中，WebUI 接口不会下发密钥原文 |
| 判定尺度 | `loose` / `standard` / `strict` |
| 单张超时 | 默认 30 秒 |
| 送审最长边 | 等比缩小上限，默认 1024 |
| 审核服务异常时放行 | 开启（默认）时审核报错仍正常出图；关闭时审核失败也拦截 |

### 判定尺度

审核模型独立给出两个维度：`level`（成人内容）和 `guro`（血腥猎奇）。

| 尺度 | 拦截的成人内容 | 拦截的猎奇内容 |
| --- | --- | --- |
| 宽松 loose | 明确露骨 | 严重血腥、肢解 |
| 标准 standard | 性暗示及以上 | 轻微血迹及以上（泳装、运动装等擦边放行） |
| 严格 strict | 擦边及以上 | 轻微血迹及以上 |

### 命中后的警告

```text
@发送者
【图片安全审核拦截】你发送的图片未通过内容安全审核，已拒绝进入绘图流程。
命中类型：成人内容 + 血腥猎奇
判定结果：成人内容等级 explicit；猎奇等级 severe；模型说明：裸露与血腥
请撤回或更换图片后重试。
```

> 💡 先在 WebUI 点 **「测试审核链路」**：用一张纯灰小图请求审核模型，确认地址、密钥和模型都可用后再开开关。

## 🔧 工作流与模型要求

插件**不会覆盖**你的原始工作流。首次加载时，会基于配置里的原始工作流，在插件目录下生成独立的 API 工作流副本：

```text
workflows/文生图.json
workflows/图生图_qwen_edit.json
workflows/图生图_flux2_klein.json
workflows/高清放大.json
workflows/洗图.json
workflows/扩图.json
workflows/多角度.json
```

原始工作流用到的自定义节点必须已装在 ComfyUI 里。插件只能**提交**工作流，不能替你安装节点。

### Qwen 图生图默认配置

可在 WebUI「图生图」页面修改：

```text
img2img_unet_name     = Qwen-Rapid-NSFW-v23_Q3_K.gguf
img2img_clip_name     = Qwen2.5-VL-7B-Instruct-abliterated.Q4_K_M.gguf
img2img_vae_name      = qwen_image_vae.safetensors
img2img_lora_name     = （独立 LoRA，可留空关闭）
img2img_lora_strength = 0.8
img2img_engine        = qwen
```

### Flux2 图生图默认配置

位于 WebUI「图生图 Flux2」页面，**使用独立字段，不会读取上面的 Qwen 配置**：

```text
img2img_flux2_unet_name = flux-2-klein\flux-2-klein-9b-fp8.safetensors
img2img_flux2_clip_name = qwen_3_8b_fp8mixed.safetensors
img2img_flux2_vae_name  = flux2-vae.safetensors
img2img_flux2_lora_name = （独立 LoRA，留空关闭）
```

Flux2 源工作流路径可在 WebUI 配置。插件启动时会把它转换成 `workflows/图生图_flux2_klein.json`，**不改写源文件**。默认工作流支持 1~3 张参考图（第一张主参考，第二三张接入后续参考条件链），超过 3 张只取前三张。

> Qwen 图生图需要 **ComfyUI-GGUF**，以及较新 ComfyUI 内置的 Qwen Image Edit、Flux Kontext、CFGNorm 和 AuraFlow 节点。

## 🔍 故障排查

### ComfyUI 未连接

```text
/comfy状态
```

确认 ComfyUI 已启动、地址填写正确。已在「绘图限额与 ComfyUI 控制」填写管理员 ID 时，也可以发 `/comfy打开`。

### 模型或 LoRA 不存在

用 `/画图配置` 查看模型目录和 LoRA 目录，确认文件已放进 ComfyUI 对应目录，然后在 WebUI 刷新模型列表。

### 批量导入 LoRA 部分失败

WebUI 的批量导入面板会列出**每个失败文件的原因**，常见情况：

- 文件已存在 → 先删除原文件，或改用 C 站下载的“允许覆盖同名文件”
- 后缀不支持 → 仅支持 `.safetensors` / `.pt` / `.ckpt` / `.bin`

### C 站下载失败 / 提示需要 API Key

1. 优先把「C 站下载方式」设为 `auto` 或 `nokey`
2. 若模型页解析失败，直接复制模型页的**下载直链**（形如 `.../api/download/models/版本ID`）再下载 —— 直链零解析、最稳
3. 只有下载受限 / 私有模型时才需要 API Key，此时把方式设为 `token` 并填写「CivitAI API Key」

### 工作流节点缺失

看 ComfyUI 控制台的节点名称，把缺失的自定义节点装上。插件无法代装节点。

### 生成黑图或失败

先在 ComfyUI WebUI 里**单独运行**对应 API 工作流，确认模型、VAE、采样器、放大模型和节点都正常，再用 `/工作流` 选对文件。

### 图生图没生效我选的文生图 LoRA

这是**预期行为**。图生图只受「独立 LoRA」影响（见上文【特别标注】）。要在图生图里用某个 LoRA，把它设到图生图页面的“独立 LoRA”，或在指令里显式写简称。

### 审核总是放行 / 什么都不检测

1. 总开关已开，且对应方向的名单包含当前群号或写了 `*` / `全部`
2. 「审核服务地址」和「审核模型」都已填写（只填一个时日志提示「审核模型未配置」并放行）
3. 点「测试审核链路」验证；模型必须是多模态模型
4. 日志出现 `图片审核失败` 说明接口报错，是否拦截取决于「审核服务异常时放行」

### 审核误拦正常图片

把「判定尺度」从 `严格` 调到 `标准` 或 `宽松`，或把该群移出名单。审核是**概率判定**，多模态模型对小众画风、夸张二次元构图和艺术化人体可能给出偏高等级。

## 🔐 数据与隐私

- 插件运行数据保存在 **AstrBot 的插件数据目录**，不写入公开仓库
- API Key 只用于请求你配置的 AI 服务，**不会**通过状态接口返回到浏览器
- 开启图片安全审核后，被检测的图片会以压缩后的 base64 发送到你在「审核服务地址」填写的**第三方多模态服务**。送审前会等比缩小到「送审最长边」以内（默认 1024）并转 JPEG，但仍是原图内容
- 如果不想把图片发给外部服务，请**保持审核总开关关闭**
- C 站「免 API 下载」模式**不会发送任何密钥**，只访问你提供的链接
